# Agent 设计细节

Agent 在 AuctionNet 的每个决策步执行一次 `observe → analyze → use tools → decide → guard → act → feedback`。状态只包含当前广告主可见信息、历史实际执行结果以及静态聚合 KB。当前对手隐藏出价和未来流量不进入上下文。

三个分析 skill 位于 `autobid_agent/skills/`：`market_value` 判断流量价值与历史市场参考，`budget_control` 判断预算节奏和 CPA 风险，`experience_review` 检查历史赢价与可复用经验。三项分析在同一次模型请求中输出各自的 `conclusion`、`data.signal`、`data.direction`、`evidence_ids` 和 `uncertainties`。数值证据由代码附加，证据引用需要能解析到输入。

四个算法工具是 AuctionNet 官方 BCQ、OnlineLP、IQL、MOPO。每步从同一个实际 state 和历史计算候选 bid；工具输出包括 bid 统计与校验信息，不提供凭空估计的单独执行 score、转化或置信度。候选推理的随机数与官方模拟器隔离。主模型在四个候选上输出 `tool_weights`、整体 `scale`、四个 `pValue` 分段系数、经验采纳 ID、简短计划和理由。程序逐 PV 加权候选 bid 后再调价，环境只执行这一组最终出价。

护栏将非法权重归零并归一化；正常自主决策至少混合两个有效算法。整体 `scale` 限制在 `[0.8, 1.2]`，高期望 CPA 风险时上限为 `1.0`；四段系数限制在 `[0.95, 1.05]`。单 PV 出价不能为负或超过剩余预算，实际总花费仍由官方环境约束。LLM、JSON 或工具失败时记录异常并回退到可用候选；无有效候选或预算耗尽时出零价。这些边界是当前工程规则，不代表已调优到最优。

短期记忆是最近四步的状态、执行动作和真实反馈，计划每步重新检查。四个已完成反馈的步骤形成一张不可覆盖的经验卡，记录候选、权重、调价、护栏、实际结果以及最多两条指导或警示原则。阶段评价只作局部诊断，不证明相对基线的因果提升；零转化时 CPA 为 `null`。

一轮结束后才将卡片原则去重归并。本轮形成的原则从下一轮开始可用；按环境指纹和广告主隔离，在轮次开始冻结快照，最多检索三条。系统分别记录检索与采纳。只有明确采纳且结果可判定时才更新原则的复用统计；原始卡始终保留。这一经验生命周期参考 [EvolveR](https://arxiv.org/html/2510.16079v2)，四步窗口和竞价评价规则是本项目的设计。

决策、模型请求、候选与最终出价数组、经验卡、护栏干预和结果保存在 `outputs/`。模型密钥只从 `DASHSCOPE_API_KEY` 或 `LLM_API_KEY` 读取，不写入日志。
